## TASK

Build **CodeMentor AI** — a complete educational web platform that:
1. Accepts C source code submitted by a student via a web interface
2. Runs a **native C static parser** (char-by-char) to compute local code metrics
3. Compiles and executes the code in a **lightweight sandbox** (fork + execve + SIGALRM timeout)
4. Sends code + metrics + gcc errors to an **AI API** (Gemini Flash or OpenAI) with a strict Socratic system prompt
5. Returns a structured feedback report to a **React dashboard** with charts and history
6. Tracks student **progression** (bugs solved, quality score, streaks) in a database

Build this project **from scratch, file by file, module by module**, in a logical order. After each module is complete, confirm with me before moving to the next.

## MANDATORY RULES TO FOLLOW

### Architecture rules
- Backend server: `libmicrohttpd` listening on port 8080
- HTTP client (to AI + Supabase): `libcurl` only
- JSON parsing: `cJSON` only
- Database (dev): `SQLite3` C API
- Database (prod): Supabase REST API via libcurl
- Sandbox: `fork()` + `execve()` with `SIGALRM` timeout (5 seconds max), `ulimit` for memory
- No use of `system()` for sandbox — use `fork/exec` directly (safer, more impressive to jury)

### AI integration rules
The system prompt injected by the C backend MUST follow this exact Socratic philosophy:
```
"Tu es un tuteur bienveillant en informatique à l'ESISA.
Un étudiant te soumet son code C et son erreur de compilation/exécution.
RÈGLES ABSOLUES :
1. Ne donne JAMAIS le code corrigé.
2. Explique la logique de l'erreur en termes simples.
3. Cite la ligne problématique probable.
4. Pose une question-guide pour que l'étudiant trouve lui-même.
5. Adapte ton niveau de langage à un étudiant de 1ère année.
Format de réponse :
- 🔍 Où est le problème
- 💡 Le concept à comprendre
- 🛠 Un indice sous forme de question"
```

The C backend must inject into this prompt: the student's code + gcc output + the local metrics (lines, functions, nesting depth, dangerous patterns detected).

### Code quality rules
- All C files: C99 standard (`-std=c99 -Wall -Wextra`)
- Memory: every `malloc` must have a corresponding `free`. No memory leaks (valgrind-clean)
- Error handling: every `libcurl`, `SQLite3`, and `cJSON` call must check return codes
- No hardcoded API keys — use `getenv("GEMINI_API_KEY")` etc.
- React: functional components + hooks only, no class components
- All API routes must return proper HTTP status codes (200, 400, 404, 500)

### File naming conventions
- C files: `snake_case.c` / `snake_case.h`
- React components: `PascalCase.jsx`
- API routes: `/api/analyze`, `/api/history`, `/api/user/:id`
